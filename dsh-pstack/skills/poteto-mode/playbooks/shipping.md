### Shipping

**You own what lands. Verify each PR independently, land only the verified run from the root, then keep your hands off the queue.** For "land the stack", "ship it", "enable merge when ready", or the second half of a stack that **Babysit** already drove to green.

This is the half after `playbooks/babysit.md`. Babysit makes a stack mergeable. Shipping decides what is actually safe to merge and lands it bottom-up through the host's PR tooling. Green is not safe, and the gap between those two words is where this playbook lives.

Pick the host CLI once, from `git remote get-url origin`: Gitea → `tea`, GitHub → `gh`. Every PR operation below goes through that CLI.

1. **Verify every PR independently before arming anything.** One subagent per PR, not batched, each a DSH subagent, each exercising the real surface (available project UI or CLI verification tooling) against parent versus head. Each returns `PASS`, `PASS+NOTES` or `FAIL` and posts that verdict on its own PR so the record outlives the chat. Safe means a verdict from an agent that did not write the code. CI green is not a verdict, and an approving bot review is not a verdict.
2. **Land only the contiguous verified run rooted at the bottom.** Walk up from the lowest unmerged PR and stop at the first one without a passing verdict, where both `PASS` and `PASS+NOTES` pass. A verified PR sitting above an unverified one is not landable, because merging it would pull the gap in underneath it. Report the ceiling as a PR number and say what breaks the chain.
3. **Re-check that the verdicts still describe the code.** A restack rewrites every SHA above it and silently invalidates every verdict without touching a single check. Compare `git patch-id` at the verdict SHA against the current head before trusting an older verdict, and re-verify anything that actually drifted. Twenty-one verdicts went stale this way in one run with no signal at all.
4. **Arm the host's auto-merge only where it is safe, then merge bottom-up.** No merge queue spans a stacked branch set on either host, so the run drains by explicit merges in order. Arm the host auto-merge when it exists and the stack rules allow it (Gitea: merge-when-checks-succeed on the PR; GitHub: `gh pr merge <n> --auto`); otherwise merge each PR explicitly once it is at the frontier. Either way, the frontier PR merges first, and the next one follows only after the parent ref advanced.
5. **Never auto-merge a child of an unmerged parent.** Only the root targets protected trunk. Every child targets its parent branch and already reads mergeable, so an armed child merges into its parent immediately and collapses the stack into itself. Sequential frontier merges are what keeps the chain. If a previous agent armed a child, disarm it (`gh pr merge <n> --disable-auto`, or the host UI's auto-merge toggle) and confirm the field is back off.
6. **Do not read an absent auto-merge field as proof of anything.** On a stack, children may report no auto-merge state until their parent has merged. An unarmed reading is meaningless; confirm arming from the host's own PR state, and if you cannot, say so rather than inferring it.
7. **Once the run is draining, stop touching the stack.** No rebases, no restacks, no speculative pushes, and no re-targeting of branches that are mid-merge. Never force-push a branch whose parent just merged without re-checking the new base first. Independent work gets re-parented onto trunk and shipped on its own.
8. **Watch the drain, do not drive it.** Run a background polling job over the verified run, re-armed after any verdict you act on, until COMPLETE at the ceiling. ADVANCE is progress, not termination. Parent refs change as each PR merges; that is the drain working, not damage. Report each merge and the new ceiling. If the queue stalls, diagnose before mutating, because a stalled queue and a broken stack look identical from the outside.
9. **Stop at the ceiling.** When the verified run is merged, report what landed, what the next unverified PR is, and what verifying it would take. Extending the run is a new pass through step 1, not a judgment call you make at 3am.

**Reply:** the verified run and its ceiling, each PR's verdict and who produced it, what you armed and how you confirmed it, what landed, and what the next gap needs.
